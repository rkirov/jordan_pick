# lean-eval `jordan_curve` submission

Solver-owned files for the lean-eval problem
<https://lean-lang.org/eval/problems/jordan_curve/>: a continuous injection
`S¹ → ℝ²` has a complement with exactly two connected components.

Generated by [`scripts/make_jordan_submission.sh`](../../scripts/make_jordan_submission.sh)
from the main-branch development; re-run it to refresh.

## Status

The proof is **sorry-free**, **axiom-clean** (`[propext, Classical.choice,
Quot.sound]`), **self-contained against Mathlib** — no dependency on the Pick
engine and **no vendored/third-party code** (the one non-trivial topological
input, that a once-around loop of the circle is not null-homotopic, is proved
directly from Mathlib's covering-space path lifting).

## Layout (solver-owned parts of the eval workspace)

```
Submission.lean          -- restates `jordan_curve` in the `Submission` namespace,
                            delegates to the proof (`_root_.JordanCurve.jordan_curve`)
Submission/
  Root.lean              -- the Maehara reduction + eval statement (our `JordanCurve` module)
  Arcs.lean              -- circle/arc scaffolding
  Counting.lean          -- `Nat.card (ConnectedComponents …) = 2` plumbing
  Brouwer.lean           -- Brouwer FPT for ℝ² (no-retraction → disk → convex-compact)
lakefile.toml            -- for LOCAL building only (see note)
lean-toolchain           -- v4.31.0
```

All module imports are re-rooted `JordanPick.JordanCurve.* → Submission.*`.

## Submitting

1. Obtain the lean-eval workspace `generated/jordan_curve/` (from the
   `leanprover/lean-eval` benchmark repo). It supplies the **trusted** files
   `Challenge.lean`, `Solution.lean`, `config.json`, `lakefile.toml` — do not
   edit those.
2. Copy this `Submission.lean` and this `Submission/` directory into that
   workspace (they are the solver-owned parts).
3. **Match the toolchain.** This proof is verified on **Lean/Mathlib v4.31.0**.
   If lean-eval pins a different Mathlib revision, the topology-heavy code
   (especially `Brouwer.lean`'s covering-space lemmas) may need porting.
4. `lake build`, then
   `lake exe lean-eval validate-submission --file generated/jordan_curve/Solution.lean`.
5. Open a submission issue at
   <https://github.com/leanprover/lean-eval-submissions>.

The `lakefile.toml`/`lean-toolchain` here are only for building this library in
isolation; in the real workspace the harness provides its own.
